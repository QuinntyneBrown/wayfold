Pattern

Empty and error states

When a Wayfold list has nothing to show, or a page cannot load, the page keeps its heading and filters and puts one plain message in the space the content would fill, with one way forward. Four cases cover every screen: empty, no results, load error, and the whole-page not-found and server-error pages.

Overview

Empty and error states replace the results region only. The site header, the .page-head with its h1, and the search filters stay in place so the member can change the query or move on without losing their bearings. A message is a .card.stack (empty, no results, not-found) or an .alert--danger with a retry button (load error).

Structure

  1. Keep the page chrome: header, .page-head, filters.
  2. Place the message where the results grid would be.
  3. Heading level continues the page outline (h2 under the page h1).
  4. One sentence of cause and next step; one primary action, never two.

Responsive behaviour

The card fills the .container width at every breakpoint; text wraps at its measure. On phones the filters stack above it, so the message stays directly under the control that caused it. The retry and primary buttons keep a 44 by 44 CSS pixel target. Nothing is hidden at narrow widths and the content reflows at 320 CSS pixels without horizontal scroll (L2-015).

Accessibility

  • Load errors use role="alert" so the failure is announced once on arrival; empty and no-results messages are static content, and the results count line (<p role="status">) announces "0 vehicles" after a filter change.
  • Not-found and server-error pages set document.title to their heading ("Page not found — Wayfold") and focus main on load.
  • The message heading continues the outline; never skip to h3 or use a bold paragraph.
  • Colour is never the only signal: the alert has a title in words.

Content

  • Say what is empty, in the screen's words: "No vehicles listed yet", "No cars in your garage yet", "No providers match".
  • No results names the filters when it can and offers "Clear filters".
  • Errors say what failed and that nothing was lost: "Could not load your inventory. Your listings are safe."
  • No blame, no jargon, no status codes in copy. Canadian spelling.

Do and don't

Sources

Mocks: every empty, error and no-results state listed under States, plus not-found and server-error. Requirements: L2-008, L2-015, L2-021, L2-029, L2-031. Components: Card, Alert, Button.

Drift

  • All six empty mocks share "Nothing here yet / New activity will appear here as people join the community / Browse again", wrong for a garage or dealer inventory. Resolution: per-screen copy and create actions as above.
  • vehicles/no-results says "Try another category"; vehicles has no category. Resolution: name make and municipality.
  • Every load error uses "Could not load this page"; the Try again button sits outside the alert. Resolution: name the content; keep the button directly after the alert.
  • not-found and server-error share the card body copy; server-error has no Try again. Resolution: server error may add Try again ahead of Go home in a later mock revision; documented, not invented here.
