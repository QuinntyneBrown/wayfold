Pattern

Dialogs and overlays

Wayfold uses three overlays: a modal dialog for short tasks that belong to the page behind it (add a car, ask about a deal, message the seller, recommend, delete a vehicle), a full-screen sheet for the site menu below LG, and a popover for the account menu. Each one names itself, traps focus, and gives focus back to the control that opened it.

Overview

An overlay interrupts. Use one only when the task is short, belongs to the current page and the member should come back to exactly where they were: the vehicle detail page after messaging a seller, their garage after adding a car. Anything longer, such as listing a vehicle for sale or a business profile, is a full page (vehicle editor, provider editor), not a dialog.

Components: Dialog, Sheet, Popover, plus Button, Alert and the form pattern inside them.

Structure

Every dialog has the same four parts: header (title, optional one-line description, Close), body, and footer with the secondary action first and the primary last. The backdrop sits under the panel; the page behind is inert.

Responsive behaviour

  • Below SM the dialog panel docks to the bottom edge at full width (place-items: end center); from SM it centres. The panel never exceeds 100dvh minus --space-12; the body scrolls and the footer stays sticky.
  • The site menu is a full-screen sheet below LG and is not used from LG, where the header shows the links inline.
  • The account popover is anchored to the avatar button and stays inside the viewport (max-width: min(20rem, 90vw)).
  • Footer buttons wrap; at 320 px wide they stack without horizontal scroll (WCAG 1.4.10).

Accessibility

  • role="dialog", aria-modal="true", aria-labelledby the title and aria-describedby the description. Use the native <dialog> with showModal() in production so the page behind is inert.
  • Focus moves into the overlay on open, is trapped while it is open, and returns to the opener on close (WCAG 2.4.3). The focused control is never hidden by the sticky footer (WCAG 2.4.11).
  • The Close icon button is 44 px and named "Close"; the sheet's Close is a <button>, not a link.
  • Errors and failures use role="alert"; success uses role="status".

Content

  • Title states the task or asks the question: "Add a car to your garage", "Delete this vehicle?". Sentence case, no full stop unless it is a question.
  • Description is one sentence about the consequence: "Your question and answers will be public."
  • The primary button repeats the verb and the object: "Delete vehicle", "Post question", "Send message", "Post recommendation". Never "OK" or "Yes".
  • Put limits in the label: "Your question (up to 1000 characters)". Mark optional fields "(optional)".

Do and don't

Sources

Mocks: add-car, ask-expert, contact-dealer, delete-vehicle, recommend, site-menu, account-menu.

Drift

  • account-menu: role="dialog" aria-modal="true" wrapping a role="menu" of links, and .account-menu has no styles. Resolution: a non-modal popover with a plain list of links; styles proposed in .cache/css-patterns-dialogs.css.
  • site-menu: Close is a link to the home page. Resolution: a button that closes the sheet and returns focus to the menu button.
  • ask-expert/success and contact-dealer/success: "Posted · Your message is available now" and Done links to the feed. Resolution: task-specific copy; Done closes and returns to the vehicle.
  • delete-vehicle: opened from "Delete selected vehicle", a link with no selection on dealer-inventory. Resolution: a Delete button per listing opens the dialog.
  • contact-dealer: title "Message the seller" while the file is named contact-dealer and it also serves private sellers. Resolution: keep "Message the seller" as the copy.
