Overview

Wayfold meets WCAG 2.2 AA on every screen (L2-016). The design system makes the common cases automatic: one focus ring, 44px targets, tokens that pass contrast in both themes, and components with the right roles. This page lists what each page must still do.

Focus

View dealer profile
The 2px accent outline, 3px offset; inputs recolour their own edge instead.

Every interactive element shows the ring on keyboard focus (2.4.7, L2-016.2); it is never removed, and it is not hidden by sticky content (2.4.11). The skip link is the first focusable element on every page.

Targets

Controls are 44px tall; small buttons are 36px tall but keep a 44px hit area. Nothing is smaller than 24px (2.5.8).

Contrast

Text 4.5:1, control edges, focus and meaningful icons 3:1, in both themes (1.4.3, 1.4.11, L2-016.4). The checked pairs are on Color.

Forms and errors

Enter your question.

A visible label, and an error tied to the field with aria-describedby.

Every field has a visible label. On submit, an alert with role alert summarises ("Check these fields"), each invalid field gets aria-invalid and an error linked by aria-describedby, and focus moves to the first invalid field (3.3.1, 3.3.3, L2-016.3).

Announcements

Result counts ("248 vehicles · Newest first") and "Loading…" use role="status"; loading regions set aria-busy. Toasts render into a polite live region; error toasts use role="alert" (4.1.3).

Images

Vehicle photos name the vehicle and the view: "2021 Honda Civic Sport, front view". Avatars with initials are aria-hidden next to the visible name. Decorative SVGs are aria-hidden.

Page checklist

  • lang="en-CA", a unique title, one main, one h1
  • Skip link to #main
  • Landmarks: header, primary nav, main, footer nav, each labelled when repeated
  • Headings in order
  • Every control named; icon-only buttons have aria-label
  • Ratings, verification and errors in words, not colour
  • Works at 320px and 400% zoom
  • Passes axe with no AA violations (L2-016.1)
