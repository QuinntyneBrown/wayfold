Site header

The top bar on every Wayfold page: the wordmark with its Toronto tag, the four sections, the one main action ("Sell your car" for members, "Create account" for visitors), the account avatar, and below 768px a Menu button that opens the site menu.

Overview

The header is the same on every page so a member always knows where they are and how to get to vehicles, providers and products. It comes in three versions:

  • Signed in: Feed, Vehicles, Providers, Products, a primary small "Sell your car" and the avatar that opens the account menu.
  • Signed out: Vehicles, Providers, Products, "Sign in" and a primary small "Create account". There is no Feed link: the feed needs sign-in (L2-039.2).
  • Auth: the wordmark only, on sign-in and sign-up, so nothing pulls the visitor away from the form.

Below 48rem the section links, the main action and the avatar collapse into one "Menu" button that opens the site menu sheet (L2-015.4).

Anatomy

  1. Wordmark.wordmark: "Wayfold" in --text-wordmark, a link home (the feed when signed in).
  2. Area tag.wordmark__tag: "Toronto" in a hairline pill. Hidden below 24rem.
  3. Section links.site-nav__link: muted text, current section in default ink and semibold with aria-current="page".
  4. Main action.btn.btn--primary.btn--sm: "Sell your car" or "Create account". The only filled control in the header.
  5. Avatar.avatar-btn with .avatar initials; hidden name "Account menu for Tendai Mensah".
  6. Menu.btn--ghost.site-nav__menu: phones only; replaces items 3–5.

Sizes

One size. --layout-topbar-height is 64px on phones and 80px from 48rem; every target in it is at least 44px tall.

Expanded
  • The current section is shown by weight and ink, not colour alone, and announced by aria-current="page". Feed, Vehicles, Providers and Products are the only sections that take it; detail pages (a vehicle, a provider) mark their parent section.
  • There is no loading or error state: the header is server-rendered with the page. While a page loads (aria-busy on main) the header stays usable.

Responsive behaviour

  • Below 48rem (L2-015.4): .site-nav__extra items and the avatar hide; .site-nav__menu shows. The header holds two targets: the wordmark and Menu, 8px apart.
  • From 48rem the Menu button hides and everything is inline. Between 48rem and 62rem the link padding drops to 8px so the signed-in header fits 768px.
  • Below 24rem the Toronto tag hides so the header never scrolls sideways at 320px.
  • The header spans the container (--layout-container-max) and uses the page margin, so its edge lines up with the page head.

Theming

The header has no surface of its own: it uses --color-bg-canvas, so it merges with the page in both themes. Links use --color-fg-muted moving to --color-fg-default; the main action inherits the primary button's ink, which flips light in dark.

Accessibility

Role and pattern

<header> (banner) holding <nav aria-label="Primary">. Links are links; the avatar and Menu are <button>s because they open something on this page. Menu has aria-haspopup="dialog" and aria-expanded; the avatar has aria-expanded and controls the account menu.

Keyboard

KeyAction
TabWordmark, then each link, the main action, the avatar (or Menu on phones), in visual order.
EnterFollows a link; opens the account menu or site menu.
SpaceOpens the account menu or site menu.
EscCloses whichever opened, and focus returns to the avatar or Menu.

Labelling

The avatar's initials are aria-hidden; its name is the hidden "Account menu for Tendai Mensah". Menu keeps its visible word; the icon is decorative.

The area tag's border is decorative; the tag's text carries the meaning and meets 4.5:1 as --color-fg-muted.

Touch

Every target is 44px tall; on phones the two remaining targets sit 8px apart.

Content

  • Section names are single plural nouns: Feed, Vehicles, Providers, Products.
  • The main action is a verb phrase: "Sell your car" (members), "Create account" (visitors). Not "Post" or "Register".
  • The wordmark is always "Wayfold" with the "Toronto" tag; never a church name or a slogan.
  • The avatar shows two initials; its hidden name uses the member's display name.

Drift found:

  • The avatar is an <a> to the account-menu mock with aria-haspopup="menu" in all 75 signed-in mocks. Resolution: a <button aria-haspopup="true" aria-expanded>; the account menu is a disclosure of links (see Popover).
  • Menu is an <a> to the site-menu mock. In product it is a <button aria-haspopup="dialog" aria-expanded>.
  • Only list pages set aria-current; vehicle-detail, provider, member and the editors mark no section. Resolution: detail pages mark their parent section.
  • The wordmark goes to home/feed when signed in but home/default on signed-out pages; that is intended (the feed needs sign-in) and kept.
