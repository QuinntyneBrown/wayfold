Container and page layout

The handful of layout classes every Wayfold page is built from: a centred container, vertical stacks, wrapping clusters, the page head, three card grids, the two-column detail layout and the narrow auth column.

Overview

Layout classes position content; they have no colour, border or type of their own (except .page-head and .eyebrow). Pick by page type:

  • Browse and feed pages: <main class="container stack"> with a .page-head, then a grid (.vehicle-grid for vehicles and inventory, .directory-grid for providers and products, .garage-grid on a profile).
  • Detail pages (vehicle, provider): .container.stack with .detail-layout: content on the left two thirds, the price rating, seller and actions on the right.
  • Forms (settings, editors): .container.container--narrow.stack, 42rem wide for a readable line.
  • Sign in and sign up: <main class="auth"> with .auth__head: a 28rem column.

.stack spaces children vertically (16px; .stack--lg 32px), .cluster wraps a row of buttons or tags with 12px gaps, and .section-gap adds the large gap before a new page section.

Anatomy

  1. Container.container: up to --layout-container-max, side padding --layout-margin (16px phone, 32px from 48rem).
  2. Page head.page-head: the page's <h1> and a muted one-line summary, 24px block margin.
  3. Cluster.cluster: a wrapping row with 12px gaps.

States

Layout classes have no states. Loading pages set aria-busy="true" on <main> and fill the same grid with skeleton cards so nothing shifts when results arrive.

Responsive behaviour

  • Grids: one column below 576px (L2-015.2), two or more from 992px (L2-015.3); min(100%, 18rem) stops a column overflowing at 320px.
  • .detail-layout becomes one column below 48rem.
  • --layout-margin grows from 16px to 32px at 48rem; content never touches the screen edge.
  • No horizontal scroll at 360, 576, 768, 992 or 1200px (L2-015.1).

Theming

Nothing to theme: only .page-head p and .eyebrow set a colour, both --color-fg-muted.

Accessibility

Structure

One <main id="main" tabindex="-1"> per page holds the layout; the page head holds its only <h1>. Grids are <ul> so a screen reader announces the count ("list, 12 items"). The detail aside is an <aside> with a name. DOM order matches visual order at every width.

Reflow

Every layout reflows to one column at 320px without loss (WCAG 1.4.10).

Contrast

Page head summary and eyebrow

Content

  • Page head: the page's name as the h1 ("Vehicles", "2021 Honda Civic Sport") and one muted sentence of context.
  • Eyebrow: kind, then area, separated by a middle dot: "Mechanic · Toronto". No trailing space.

Drift found:

  • .eyebrow is used by the provider mocks but has no rule in components.css. Resolution: added (overline, muted).
  • Eyebrow text ends with a stray space ("Dealer · Scarborough "). Resolution: trimmed.
  • Provider pages repeat the name and kind in the page head and again in the first card. Resolution: page head only.
  • .vehicle-grid uses auto-fit while garage and directory grids use auto-fill, so one vehicle stretches full width. Resolution: flagged; all three should use auto-fill.
  • A generic .grid was asked for but no mock uses one and components.css has none; not documented.
