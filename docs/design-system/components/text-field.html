Text field

A labelled single-line input with help and error text. It carries every form in Wayfold: signing in, settings, listing a vehicle and searching.

WCAG 2.2 AAStatus: stable.field.input

Overview

A labelled single-line input: email and password on sign-in and sign-up, display name and home church in settings, year, make, model, price and mileage in the vehicle editor, and the search box in every filters row. Use a textarea for anything that runs to sentences, and a select for a fixed list such as GTA municipality.

A field is a .field wrapper holding .field__label, the .input, and optionally .field__help and .field__error. The same wrapper and messages serve textarea and select.

Anatomy

  1. Label<label for>, always visible, above the input. Optional fields say "(optional)"; required fields say nothing.
  2. Input.input: full width, 44px, 1px --color-border-strong, --radius-md.
  3. Help or error.field__help (muted) or .field__error (danger, warning glyph), tied with aria-describedby. An error replaces the help.

Variants

Types used by the mocks: email, password, numeric text (price, mileage, year), search and file. Each keeps the same look.
HTML
<div class="field"><label class="field__label" for="v-email">Email</label><input class="input" id="v-email" type="email" autocomplete="email" value="tendai@example.ca"></div>
          <div class="field"><label class="field__label" for="v-pass">Password</label><input class="input" id="v-pass" type="password" autocomplete="current-password" value="correct-horse"></div>
          <div class="field"><label class="field__label" for="v-price">Price (CAD)</label><input class="input" id="v-price" type="text" inputmode="numeric" value="29500"></div>
          <div class="field"><label class="field__label" for="v-q">Search vehicles</label><input class="input" id="v-q" type="search" value="RAV4"></div>
          <div class="field"><label class="field__label" for="v-photo">Vehicle photo</label><input class="input" id="v-photo" type="file" accept="image/*"></div>

Sizes

One size: 44px (--control-height-md) at every width, which meets the touch target.

States

Forced with data-state here; real fields use :hover, :focus-visible, aria-invalid, disabled and readonly.

Errors appear after submit, never on each keystroke. The form adds a danger alert at the top ("Check these fields") and every invalid field gets its own message (L2-016.3). While submitting, inputs stay enabled and the submit button goes busy.

Responsive behaviour

  • Fields are always full width of their column; forms sit in .container--narrow cards so lines stay readable.
  • Label, help and error wrap (overflow-wrap: anywhere); a long church name never widens the form at 360px.
  • In filters a field takes a grid column from 12rem up and a full row on a phone.

Theming

Inputs read three component tokens, --field-bg, --field-border and --field-fg, which states reassign (invalid sets --field-border: var(--color-danger-solid), disabled sets the fill to --color-bg-subtle). Shared with select and textarea.

Accessibility

Labelling

Every input has a visible <label for>. Placeholders are never a label; the mocks use none. Help and error are tied with aria-describedby; when both exist list both ids, error first.

Errors

Invalid inputs carry aria-invalid="true"; the message says how to fix it. The form-level alert has role="alert" so the error summary is announced, and focus moves to the first invalid field (L2-016.3). The error glyph is hidden from assistive technology; colour is never the only signal.

Input purpose

Set autocomplete (email, current-password, new-password, name) and inputmode="numeric" on price, mileage and year (WCAG 1.3.5).

Content

  • Labels are short nouns in sentence case: "Email", "Display name", "GTA municipality". Units go in brackets: "Price (CAD)", "Mileage (km)".
  • Mark optional fields "(optional)"; don't mark required ones.
  • Errors say what to do: "Enter a valid email", "Use at least 12 characters", "Use 80 characters or fewer". No "Invalid", no "Error:" prefix, no full stop.
  • Help text is one sentence about what happens with the value: "Shown on your profile and posts."

Drift found during extraction:

  • vehicle-editor/invalid marks year "2015" as invalid with "Enter a year". Resolution: the example shows a value that is actually wrong, with a message that says how to fix it.
  • Price, mileage and year use type="text" with no inputmode, and no input in the mocks sets autocomplete. Resolution: inputmode="numeric" and autocomplete are part of the component.
  • Optional fields write "(optional)" as plain label text; the .optional span in components.css is unused. Either is acceptable; the system prefers the span so the suffix is muted.
