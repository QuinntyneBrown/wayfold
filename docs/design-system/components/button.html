Component · Actions

Button

Buttons do something: search vehicles, publish a listing, post a question, delete a vehicle. One solid primary per screen marks the action that screen exists for.

Overview

Use a button when activating it changes something, sends a request or opens a dialog: "Search", "Post to feed", "Send message", "Delete vehicle". A page's main call to action may be a link drawn as a button when it only goes somewhere ("Sell your car", "Message seller", "Try again"). Use a segmented control to move between sections of one page, and a plain link inside running text.

  • Primary (.btn--primary, solid --color-action) is the one action the screen or dialog exists for: "Search" in the filters, "Publish listing", "Save settings", "Post question", "Sell your car" in the header.
  • Default (.btn alone, outlined pill) is every other action: "Cancel", "Try again", "Ask a question", "Comment", "Edit profile", "View listing".
  • Ghost (.btn--ghost, no border) is quiet chrome: the phone header's "Menu" and the dialogs' Close.
  • Danger (.btn--danger) names a loss and lives only in a confirmation dialog: "Delete vehicle".
  • Small (.btn--sm) is for in-row and header actions: "Like · 12" on a post, "Sell your car" in the header.
  • Icon (.btn--icon) is the square Close in every dialog header, always with aria-label.

Anatomy

  1. LabelA verb phrase in sentence case. It is the accessible name; repeated buttons add the object in visually hidden text.
  2. ContainerPill (--radius-full) with a 1px border; 44px tall (--control-height-md), 36px small; side padding --space-4 (--space-3 small). An optional 1.25em icon sits before the label, aria-hidden="true".

Variants

Variants change emphasis, not meaning. One primary per screen or dialog, placed last in a row.

Primary, default, ghost and danger, highest to lowest emphasis. Danger appears only in dialogs/delete-vehicle.

Sizes

Medium (44px) is the default and meets the 44px target everywhere. Small (36px) is used only from 48rem up; below 48rem it grows to 44px (--target-comfortable).

Heights --control-height-sm / --control-height-md; label --font-size-sm / --font-size-md; icon button is square at the medium height.

States

Hover, focus and active are forced here with data-state; real pages get them from :hover, :focus-visible and :active.

Both themes

  • Busy: aria-busy="true" with disabled. The label is hidden visually but kept, so the width and accessible name do not change; a spinner shows in the label colour. While a dialog sends, its Cancel and Close are disabled too (dialogs/*/busy).
  • Disabled is used only while a request is in flight. Wayfold never disables a submit button to signal invalid input: the member presses it and gets the field errors.
  • Expanded: the header "Menu" carries aria-haspopup="dialog" and aria-expanded.

Responsive behaviour

  • Below 48rem every small button grows to 44px, so "Like · 12" is a comfortable target on a phone (L2-015, L2-016).
  • In the filters grid the "Search" button fills its column (.filters .btn) and drops to its own full-width row on a phone.
  • The header shows "Sell your car" / "Create account" (.site-nav__extra) from 48rem; below that the ghost "Menu" replaces it and the action moves into the site menu.
  • .btn never exceeds its container (max-width: 100%). A label that would not fit at 360px gets a shorter verb phrase; it never truncates.

Theming

The button reads semantic tokens through five component tokens: --btn-bg, --btn-fg, --btn-border, --btn-bg-hover and --btn-bg-active. Variants only reassign them, so both themes come from the semantic layer.

.btn--danger {
  --btn-bg: var(--color-danger-solid); --btn-fg: var(--color-fg-on-danger);
  --btn-border: var(--color-danger-solid); --btn-bg-hover: var(--color-danger-solid-hover);
}

In dark, --color-action flips to a light fill with dark text so the primary still reads as the main action; the default button's border uses --color-border-strong, which keeps 3:1 on both canvas and dialog surfaces.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form (APG Button). Something that only navigates is an <a href> with the same classes.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order. Disabled buttons are skipped.
Enter, SpaceActivates a button. A link drawn as a button answers Enter only.
EscNo effect on the button; inside a dialog it closes the dialog like Cancel, and focus returns to the opener.

Focus

The shared ring (--focus-ring-width, --color-focus-ring) shows on :focus-visible only (L2-016.2). In dialogs/delete-vehicle "Cancel" takes initial focus, never "Delete vehicle".

Labelling

The visible label is the accessible name. The icon-only Close has aria-label="Close". The phone menu's "Close" link carries aria-label="Close menu", which starts with its visible text (WCAG 2.5.3). A busy button keeps its name.

Motion

Background, border and shadow transition over --duration-fast; active nudges 1px down. Reduced motion zeroes both. The busy spinner keeps turning because it reports status.

Content

  • Verb phrases in sentence case, Canadian English: "Publish listing", "Save settings", "Post question", "Send message", "Add car". Never "Submit", "OK" or "Click here".
  • Name the object when it helps: "Delete vehicle", "Save business profile", "Follow Priya".
  • The safe action beside a destructive one is "Cancel".
  • Counts after a middle dot: "Like · 12".
  • Three or four words; a label that wraps at 360px is too long.

Drift found during extraction:
