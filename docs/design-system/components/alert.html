Alert

An alert is an inline message about the page or form the user is on: a failed load, fields to fix, a lockout or a saved change.

WCAG 2.2 AAStatus: stable.alert.alert--danger.alert--success.alert--warning

Overview

Use an alert inside the content, above the thing it is about: "Could not load this page" above Try again, "Check these fields" at the top of a form, "Too many attempts" on sign-in, "Saved" in settings. Use a toast for a passing confirmation that is not tied to the page.

Anatomy

  1. ContainerTone fill, border and text via --alert-*.
  2. Title.alert__title: what happened.
  3. TextWhat to do next.

Sizes

One size: padding --space-4; width of its container.

States

  • Shown on load or after submit; it does not animate.
  • Removed when the condition clears (form fixed, retry succeeded).

Responsive behaviour

  • Full width of its column; text wraps (overflow-wrap: anywhere).
  • No fixed height.

Theming

Each tone sets four component tokens from --color-{tone}-bg/-fg/-border/-icon.

Accessibility

Danger and warning use role="alert"; info and success use role="status". Insert the alert into the page when it applies so the live region announces it. A form-error alert also moves focus to the first invalid field (L2-016).

Content

  • Title says what happened: "Could not send", "Saved".
  • Text says what to do: "Try again." Reassure when data is safe.
  • No "Error:" prefix; the tone and role carry it.
